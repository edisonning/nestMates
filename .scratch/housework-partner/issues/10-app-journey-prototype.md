## Question

用可点击的粗原型确定任务大厅、协作天平、动态打卡簿、心愿集市与家庭设置的导航和关键用户路径。

- 首次进入、创建或加入家庭、选择预设、找到今天要做的事的连续路径。
- 按[家务周期决议](02-task-calendar.md#answer)区分当前待办、未来预览与全部家务，验证组合筛选、搜索、空状态，以及修改和删除的生效范围；按已确认的[日期边界决议](13-calendar-boundaries.md#answer)验证首次安排、预览固定、改期取值、保存前接续说明和撤销去向。
- 从筛选或公共认领到本人打卡、看到积分与感谢，再到兑换和待履约的连续路径。
- 按[打卡与反馈决议](04-checkin-and-feedback.md#answer)，验证无必填且无耗时属性的打卡、历史补记及缺失完成日期、本人更正和撤销后的归属、比心与撤销记录留痕；覆盖提交结果不明、重试不重复计分和撒花、归档只读的页面反馈。
- 家庭设置的位置、身份提示和权限说明；任何页面都不出现切换打卡人入口。
- 按[已决家庭生命周期](01-family-membership.md#answer)验证退出影响告知与二次确认、归档历史入口和重新建家路径。
- 按[平台权限决议](09-admin-permissions.md#answer)呈现家庭停用原因与时间、历史查看、本人退出及恢复结果；不提供反馈、客服联系或账号注销入口。停用恢复的日期组合场景按[日期边界决议](13-calendar-boundaries.md#answer)验证，区分单项暂停关闭与平台停用保留，并覆盖一次性日期已过且未生成的提示。
- 验证小屏幕的信息密度、任务列表与天平的展示，保留简单撒花反馈。
- 按前序已决规则呈现单人成家等待邀请、没有任务、没有积分、没有动态和待履约等空状态。
- 验证关键失败与恢复路径的理解程度；发现规则缺口时形成新决策工单，不在原型中默默决定。
- 用户实际审阅原型后再解决，记录接受的路径与尚需处理的反馈。

### 已确认的页面路径

| 用户情境 | 保留的页面路径和反馈 |
| --- | --- |
| 首次进入与受邀 | 普通进入只提供创建家庭入口；受邀人从微信分享卡片进入邀请详情，查看家庭和邀请人后确认加入。欢迎页不设独立接受邀请按钮。 |
| 邀请伴侣 | 单人家庭从家庭设置的本人资料下方邀请伴侣；沿用邀请弹窗、分享卡片预览及撤销当前邀请的现有文案与状态。伴侣已加入后收起邀请入口。 |
| 找到并添加家务 | 任务大厅区分当前待办、未来预览与全部家务。右上角添加家务进入统一添加页，默认预设，同页切换自行创建；全选与取消全选位于预设清单之前。 |
| 做这一次家务 | 详情首层突出本人打卡、认领或接手中适用的主操作；“调整这一次”承接单次修改、跳过和适用时的放回公共池。长期安排从全部家务的管理入口进入，复制与删除收进更多操作。 |
| 修改日期和后续计划 | “仅修改本次”说明保留原计划和不改变后续安排；修改后续安排先展示保留的本次、新计划首次日期、轮流负责人及下一次安排，再确认保存。日期规则沿用已决日期边界。 |
| 打卡与查看付出 | 以本人账号打卡，无必填及耗时属性。普通和提前打卡成功后留在原任务视图，保留筛选，显示完成、积分与简单撒花；主动查看记录才进入对应动态。天平沿用已确认的双方贡献对照。 |
| 补上或修改记录 | 动态顶部“以前做过，忘记打卡了？”与“补上打卡”承接补记。本人有效记录保留一个“修改记录”，区分日期／文字更正与撤销整条打卡，并说明积分影响、操作痕迹及家务去向。 |
| 兑换与兑现 | 兑换成功直接进入待兑现。“我已收到，确认完成”与“取消并退分”上下排列、整行显示；确认完成后保留盖章反馈。卡片不提供修改备注入口，已有备注继续展示。 |
| 家庭设置 | “这个家的安排”保留全部家务、家庭心愿、积分与流水、家庭与本人资料四个常用入口；不在该分组另放已归档家庭或日期说明入口。 |
| 退出与归档 | 退出前说明双方协作结束、历史保留、待兑现取消退分，并二次确认。归档页显示只读、不可恢复，保留历史查看和重新创建或加入家庭的去向。 |
| 停用与恢复 | 显示停用原因和时间，保留可访问历史，协作操作受限；平台恢复后显示恢复提示，重新开放适用的任务操作。停用与归档的含义保持区分。 |
| 提交异常 | 明确失败说明未生效，保留输入并允许重新提交；结果不明先查询本次结果，明确查询不会发起第二笔操作，确认成功后再呈现成功反馈。 |
