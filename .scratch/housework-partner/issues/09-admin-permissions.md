## Question

在默认不查看私人留言或具体家务记录、不任意编辑积分的边界下，平台运营者实际需要哪些家庭管理、汇总指标和例外处理能力？

- 家庭列表、家庭详情各显示哪些必要信息；账号状态、停用和恢复有什么明确含义及家庭端结果。本工单承接[家庭生命周期决议](01-family-membership.md#answer)留下的平台停用问题，不能未经决策将平台停用等同于成员主动退出。
- 运行概况服务哪些运营判断，活跃家庭、完成家务、兑换与履约等候选指标采用什么口径。
- 平台需要几类管理员角色；模板维护、家庭状态操作、数据查看与操作记录分别由谁访问。
- 客服例外是否首版必需；若需要，家庭如何发起授权，允许访问哪些最少信息，何时失效，如何留痕。
- 积分争议如何处理才能保持已有账目规则，不变相提供任意改余额入口。
- 家庭删除、成员退出与客服处理的关系，以及可能影响伴侣的操作如何呈现与确认。

## Answer

### 范围与固定角色

首版平台后台负责公共模板、家庭状态、全平台运行概况及管理员权限。家庭成员与平台管理员身份分开；平台不代替成员协作，也不提供日常查看私有记录的入口。

| 能力 | 超级管理员 | 运营管理员 |
| --- | --- | --- |
| 公共家务预设、默认特权模板维护 | 可操作 | 可操作 |
| 全平台汇总运行概况 | 可查看 | 可查看 |
| 家庭列表与必要详情 | 可查看 | 不可查看 |
| 单户停用、恢复 | 可操作 | 不可操作 |
| 管理员账号、角色与启停 | 可操作 | 不可操作 |
| 管理员操作记录 | 可查看全部 | 仅查看本人记录 |
| 私人留言、具体家务、心愿内容、个人积分账目 | 不提供查看入口 | 不提供查看入口 |
| 任意改积分、代打卡、代处理兑换 | 不提供 | 不提供 |

- 管理员各用独立账号；超级管理员不得停用或降级最后一名有效超级管理员。
- 管理员被停用或降权后，已有登录会话不能继续执行原权限操作；操作执行时重新核对权限。
- 不额外设置客服或审核角色。模板操作遵循[公共家务预设与默认特权模板如何维护和生效](08-public-templates.md#answer)的既定发布、下架和恢复流程。

### 家庭列表与详情

- 列表显示家庭编号、名称、成员数、使用中／停用／归档状态、创建日期、最近协作日期。
- 详情补充成员编号、昵称、加入日期及家庭状态操作记录。最近协作日期沿用下述协作活跃事件口径，不以登录浏览代替。
- 不展示具体家务、私人留言、心愿内容或个人积分账目；不提供私有记录下钻或批量导出。
- 页面筛选与布局由[平台后台如何呈现安全且够用的运营路径](11-admin-prototype.md)验证，不能通过原型增加数据访问权限。

### 家庭停用与恢复

平台停用针对整个家庭，临时暂停协作，保留成员关系和历史；不提供个人账号封禁，也不把停用等同于成员退出或家庭归档。

| 状态变化 | 结果 |
| --- | --- |
| 使用中 → 停用 | 超级管理员单户操作，暂停家庭协作写入，保留关系、记录、积分与待兑现 |
| 停用 → 使用中 | 仅超级管理员手动恢复，继续原家庭，不新建关系或重新发放积分 |
| 使用中／停用 → 归档 | 本人主动退出触发，沿用已决整户归档、待兑现取消与退分规则 |
| 归档 → 使用中 | 首版不支持，不能借平台恢复绕过归档边界 |

- 停用期间保留登录、查看本人有权访问的历史和本人主动退出；不开放反馈或客服联系入口。
- 暂停邀请加入、家庭设置修改、家务安排、认领、打卡、补记、更正、撤销、比心、心愿及兑换处理等家庭协作操作。
- 停用本身不取消待兑现、不退分；停用期间主动退出仍按[家庭创建、邀请与成员退出如何形成闭环](01-family-membership.md#answer)完成归档与收尾。
- 停用中的家庭仍占成员的当前家庭名额；成员须本人退出后才能另建或加入家庭。邀请的原 24 小时有效期照常流逝，不因停用延长。
- 停用和恢复只支持单户、手动操作：填写双方可见的原因，展示影响并再次确认后执行，无需伴侣批准；不提供批量或定时操作。
- 双方下次进入时看到状态变化结果；停用提示显示原因和时间。失败明确提示未生效，执行时重新核对最新家庭状态；若家庭已因成员退出归档，恢复请求失败并提示已归档。

### 停用前后的待办衔接

- 停用期间不生成新待办、不把该期间记为漏做；停用前的未完成待办保留只读。
- 恢复沿原日历，不补发停用期间待办。旧周期待办若已跨下一计划日，则关闭并注明“平台停用”，否则继续保留；一次性未完成待办仍保留。
- 恢复当天及以后按原计划继续，已完成的不重复生成；原先单独暂停的家务仍保持暂停。
- 以上是平台停用的业务原则，并非把“暂停单项家务”直接扩大到全家。当天停用恢复、计划日恢复、提前完成、单次改期和轮流衔接的组合细则，由[日期调整与恢复如何避免待办重复或消失](13-calendar-boundaries.md)继续决定。

### 管理员操作留痕

- 模板变更、家庭停用恢复、管理员权限变更记录操作者、时间、对象、动作和结果；家庭停用恢复及权限变更另记录原因。
- 超级管理员查看全部操作记录，运营管理员仅查看本人记录。后台不提供修改或删除日志入口。
- 操作记录权限不等于家庭私有内容查看权限；日志不得成为绕过家庭字段边界的入口。

### 运行概况与统计口径

运行概况服务于家庭组建、持续家务协作和兑换兑现三个运营判断。提供今日、近 7 日、近 30 日，以北京时间自然日划分并包含今日，只展示全平台汇总。

| 指标 | 口径 |
| --- | --- |
| 新建家庭数 | 统计期内创建的家庭 |
| 首次双人家庭数 | 统计期内首次加入第二位成员的家庭 |
| 协作活跃家庭数 | 期内发生成功打卡／补记、兑换、盖章或主动取消兑换的家庭，按家庭去重 |
| 有效打卡数 | 按提交时间归属，含补记；撤销后扣回原提交期 |
| 兑换次数 | 按成功兑换操作时间统计 |
| 盖章次数 | 按成功盖章操作时间统计 |
| 主动取消次数 | 按成员成功取消兑换的操作时间统计，不含归档自动取消 |

- 仅登录浏览不构成协作活跃；归档自动取消与退分不计入协作活跃或主动取消次数。
- 打卡按提交时间统计，区别于协作天平按贡献统计日归集。更正实际完成日期不会把平台打卡提交移到另一期。
- 不直接用当期盖章数除以当期兑换数作为履约率，因为两者可能来自不同批次的兑换。
- 不提供按家庭贡献排名或私有记录下钻。家庭之后停用或归档不是删除既有成功事件；有效打卡按已决撤销口径另行扣回。

### 积分纠错、反馈与删除边界

- 首版暂不提供反馈：此处指用户向平台提交问题的能力，不设置小程序反馈入口、客服联系方式／复制入口、后台客服工单或客服接收回复流程；不自动上传家庭记录，也不提供客服授权查看私有记录的入口。
- 普通记错由本人按[本人打卡、更正与比心如何保持记录可信](04-checkin-and-feedback.md#answer)及[贡献积分与可用积分如何计算和更正](05-points-ledger.md#answer)处理；平台不代打卡、不代处理兑换、不任意修改余额。
- 系统故障核查既有业务事件和积分流水的一致性，技术修复只能恢复可证明的原业务结果并保留依据，无法证明时不得猜测补分。此处限定纠错原则，不增加后台手工改分或客服处理工具，不授权日常浏览家庭私人内容。
- 涉及共同账目的修复，结果、账目变化与更正原因沿用[积分决议](05-points-ledger.md#answer)的双方可见规则，在既有账目中可查；不增加反馈回复或修复通知模块。
- 首版不提供账号注销、永久删除家庭、清空家庭历史或平台代清空个人资料入口，不替成员退出或移除伴侣。本人修改昵称、头像沿用已决规则。
- 成员结束协作使用本人退出与整体归档；上述首版范围不重开历史保留、归档不可恢复及兑换关闭规则。

### 关键场景核对

| 场景 | 预期结果 |
| --- | --- |
| 运营管理员直接打开家庭详情或尝试停用 | 拒绝访问或操作，不暴露受限字段 |
| 管理员已降权，但旧页面仍显示停用按钮 | 提交时按最新权限拒绝，不改变家庭状态 |
| 尝试停用或降级最后一名有效超级管理员 | 操作不允许生效 |
| 有待兑现的家庭被停用 | 待兑现与已扣积分保留，家庭暂不能盖章或取消 |
| 停用期间一方主动退出 | 整户归档，待兑现按原规则取消并退分；不能再恢复 |
| 停用超过邀请有效期后恢复 | 旧邀请仍已过期，不补回有效时长 |
| 周期待办跨过下一计划日后恢复 | 旧待办按平台停用关闭，不补发停用期间待办 |
| 一次性待办未完成，家庭恢复 | 该待办继续保留；原单项暂停不被解除 |
| 只登录浏览的家庭 | 不计入协作活跃 |
| 上月提交打卡，本月撤销 | 扣回原提交期有效打卡数，不计为本月负的打卡提交 |
| 本期盖章来自上期兑换 | 分别按各自操作期统计，不拼成同批次履约率 |
| 停用用户查看停用提示 | 可看原因、时间、历史并本人退出；无反馈或客服联系入口 |
| 平台需要核查积分错误 | 不提供任意改余额入口；只按可核实业务结果纠错并留依据 |
