## Question

在本人账号操作的前提下，四种分配形态如何确定每次家务的责任人、允许操作与下一次安排？

- 指派任一伴侣是否需要对方接受，双方可以怎样调整既有分工。
- 公共池认领是在开始前还是完成时发生；同时认领、放弃认领与逾期未做如何处理。
- 轮流的首位成员、切换时点和中断恢复规则；跳过、逾期、撤销完成是否推进轮次。
- 提前完成、跳过、逾期与暂停的日历行为以[家务周期决议](02-task-calendar.md#answer)为前提；本工单决定其责任人与轮次含义，交叉改期行为由[日期调整与恢复如何避免待办重复或消失](13-calendar-boundaries.md)处理。
- 非责任人实际做了家务时，怎样先改变归属再以本人身份打卡；不允许替伴侣记完成。
- 成员暂时缺席时的安排，以及依据[已决家庭生命周期](01-family-membership.md#answer)停止协作后，当前分配与未来轮次如何呈现；不再设计原家庭替换成员。

## Answer

### 分配形态与适用范围

- 四种分配形态为指派给本人、指派给伴侣、公共待认领、两人轮流。称呼沿用家庭成员设置，不代表不同权限。
- 指派直接生效，无需对方接受审批；本次负责人表示当前由谁负责，不等于已完成人。只有本人能记录本人实际完成的家务，不支持代打卡。
- 轮流仅用于两位成员均已加入的家庭中的周期家务；一次性家务使用指派或公共认领。只有一位成员时沿用家庭生命周期决议中的单人使用范围，不设置不存在的伴侣为负责人。
- 双方均可调整分工，操作前说明影响，操作后在小程序内让双方看到变更。修改长期分配只影响后续新待办，当前待办保持原分配；调整当前一次使用“仅修改本次”。

### 公共认领与释放

- 公共任务先认领，再由认领人本人打卡；认领后双方可见本次负责人，认领本身不得积分。
- 同时认领只允许一人成功，另一人看到任务已被认领，不能按未认领状态继续提交。
- 认领人可以“放回公共池”，解除本次认领，双方可重新认领。双方也可通过调整本次分工，将未完成待办改派或改为公共待认领。
- 逾期本身不自动解除认领。周期公共任务到下一期时，尚未完成的旧任务转为未完成历史，新一期重新待认领，不继承旧一期认领人；一次性任务继续保留当前负责人，直到主动放回、调整或结束。
- 新一期采用已经生效的长期分配安排；上述重新待认领指长期安排仍为公共认领的家务。

### 轮流依据、启用与切换

- 两人按每次计划次序交替负责，不以实际完成为轮换条件；本次跳过或最终未完成不改变下一次的负责人。
- 每次启用轮流，包括退出轮流后重新启用，都明确选择首位成员，展示生效后的前两次安排。修改已有家务时，从修改后的首个新待办开始，当前已出现的待办保持不变。
- 本次接手只是单次调整，不算重新启用轮流，不补偿或调换后续轮次。
- 提前完成仍属于原计划的那一次，不额外推进轮流；仍遵守原计划日结束前不开放更后一期的日历限制。撤销完成也不重排后续负责人。
- 是否允许撤销、撤销后的记录与负责人怎样恢复，交由[本人打卡、更正与比心如何保持记录可信](04-checkin-and-feedback.md)确认，不从“不重排后续负责人”推断当前记录的恢复方式。

### 临时接手、缺席与暂停

- 未完成待办提供“本次由我接手”：本人确认后成为本次负责人，再以本人账号打卡，无需伴侣审批，双方可见变更。已完成记录不能通过接手改写。
- 双方均可改派未完成待办、改为公共待认领、跳过本次或暂停家务，无需另一方审批；操作前说明影响，操作后双方可见结果。
- 首版不增加成员请假功能。偶尔缺席用本次接手，持续缺席可调整长期分工，双方都不需要执行时可暂停家务。
- 暂停期间沿原日历推算轮流归属，但不生成待办、不记未完成，也不要求补做。恢复后按原日历对应的成员继续，不按暂停前最后一次实际完成人重新推算。
- 当天暂停恢复、修改周期或本次日期等组合场景的日期与轮次对应，由[日期调整与恢复如何避免待办重复或消失](13-calendar-boundaries.md)继续明确，不改变已决的按计划轮流原则。

### 同时操作与已完成记录保护

- 打卡与改派、接手等分工变更同时发生时，先成功的操作生效，后续操作必须以当前状态判断能否继续。
- 分工变更先成功：原负责人的旧打卡提交提示“分工已更新”，展示当前负责人，不按旧归属完成。
- 打卡先成功：后来的接手或改派不得修改该条已完成记录。
- 已完成记录需要更正时走打卡工单确定的更正流程，不能通过改派、接手、跳过或暂停改写历史；本工单不预设具体更正权限和期限。

### 家庭归档后的收尾

- 沿用[家庭生命周期决议](01-family-membership.md#answer)，归档结束整个家庭的协作，不提供原家庭替换伴侣或恢复协作。
- 当前未完成待办统一关闭，注明“家庭已归档”，保留关闭前的负责人或待认领状态，不记为成员未完成。
- 停止后续安排与轮流计算。原家务分工仅供查看，不再提供认领、接手、打卡或恢复入口，历史完成与贡献保留。

### 关键场景的预期结果

| 场景 | 预期结果 |
| --- | --- |
| 将下次换床品指派给伴侣 | 直接生效，无需接受审批，双方可见分工 |
| 双方同时认领清洗油烟机 | 只有一人成功，另一人看到已被认领 |
| 认领人尚未完成就放回公共池 | 本次重新待认领，不因认领或放回获得积分 |
| 公共每日家务认领后一直没做，到下一期 | 旧一期转为未完成历史，新一期重新待认领 |
| 公共一次性家务已认领且逾期 | 保留原负责人，不因逾期自动放回公共池 |
| 本周轮到本人却未完成或主动跳过 | 下周仍按计划轮到伴侣 |
| 本周轮到伴侣，但本人实际完成 | 先本次接手，再本人打卡，不改变下周原定负责人 |
| 周六提前完成原定周日的轮流家务 | 归于该周日的一次，不额外推进轮次或立即开放更后一期 |
| 原计划三周依次为本人、伴侣、本人，中间一周暂停 | 第三周恢复仍归本人，暂停一周不生成任务、不记未完成 |
| 退出轮流后重新启用，已有当前待办 | 重新选择首位成员，从首个后续新待办起轮流，当前待办不变 |
| 伴侣接手成功后，本人提交旧页面的打卡 | 提示分工已更新，展示当前负责人，不按旧归属完成 |
| 本人打卡成功后，伴侣提交接手 | 不改写已经完成的记录 |
| 家庭归档时还有已认领和待认领任务 | 均注明家庭已归档并关闭，保留原归属，不记为成员未完成 |
