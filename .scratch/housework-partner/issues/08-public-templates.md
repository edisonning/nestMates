## Question

平台如何维护公共家务预设与默认特权模板，家庭如何选用它们，才能在模板更新后保留家庭自己的安排与承诺？

- 两类模板各需哪些内容字段、分类、排序与可见状态；哪些内容允许家庭修改。遵守[打卡与反馈决议](04-checkin-and-feedback.md#answer)，不设置家务预计耗时字段；心愿服务内容中的时长描述不受影响。
- 首版 20+ 家务预设如何覆盖六个功能区与不同周期，以什么标准判断实用、可理解。
- 发布、修改、下架、误操作恢复各会影响哪些家庭内容。
- 一键载入、部分载入及默认特权首次出现的时机；家务重复载入采用[已决同源去重与主动复制规则](02-task-calendar.md#answer)，不重开该选择。
- 家务模板修改沿用[已决独立副本规则](02-task-calendar.md#answer)；默认特权模板修改是否影响家庭心愿或已兑换承诺，遵守履约工单决议。
- 确认内容维护和生效策略；本工单不把批量制作完整内容库当作决策的替代。

## Answer

### 模板内容与家庭修改边界

| 内容 | 公共家务预设 | 默认特权模板 |
| --- | --- | --- |
| 业务内容 | 名称、完成范围说明、六区归属、建议周期、建议家务分值 | 名称、明确的服务内容、建议兑换积分 |
| 分类 | 厨房烹饪、客厅公共区、卧室衣物、卫浴清洁、阳台宠植、综合事务；每项归一个区 | 首版不增加特权分类 |
| 分值 | 10、20、30……100 共十档 | 大于 0 的整数，由家庭自行约定，不套用家务分值范围 |
| 平台维护内容 | 排序、发布状态 | 排序、发布状态 |
| 家庭选用后的修改 | 可修改本家庭的业务内容，遵守已有家务修改生效规则 | 可修改本家庭内容与价格，遵守兑现人重新确认规则 |

- 家务不设置耗时、独立难度属性，也不由平台模板指定某个家庭成员。特权服务中的“按摩 20 分钟”等内容描述仍可保留。
- 家庭不能修改平台模板的排序或发布状态。公共家务预设和默认特权模板选用后均形成家庭独立内容，平台更新、下架或恢复不覆盖家庭安排、心愿及已有兑换约定。
- 家务修改与历史保留沿用[家务周期决议](02-task-calendar.md#answer)，心愿修改、确认及已有兑换约定沿用[心愿履约决议](07-wish-fulfillment.md#answer)。

### 家庭选用入口与步骤

- 创建家庭后提供家务预设选用入口，允许跳过，后续仍可进入；不会自动为新家庭载入全部家务。
- 家务支持全选或部分勾选。预览展示名称、周期、分值、分工与首次计划日期，允许逐项调整；需要补齐的计划参数在确认前填写。
- 新载入家务默认使用公共待认领分工，不自动指派伴侣或启用轮流。主动选指派时明确成员；选轮流时沿用[分工决议](03-assignment-rotation.md#answer)，选择首位成员并展示前两次安排。
- 首次日期取值、默认起点、能否选择过去日期及是否补造创建前任务，统一由[日期调整与恢复如何避免待办重复或消失](13-calendar-boundaries.md)决定；本工单不将任何日期算法或默认日期确认为规则。
- 首次进入心愿集市展示默认特权推荐，主动选用才形成家庭心愿。特权逐项核对内容与价格，明确由本人兑现或希望伴侣兑现；由本人提供的需明确本人确认才开放，希望伴侣提供的保持不可兑换，等待伴侣本人确认。
- 单人阶段可先保存心愿意向，不虚构兑现人，伴侣加入后再确定兑现人并确认；兑换资格继续遵守既有仅兑换本家庭伴侣承诺的规则。
- 归档家庭沿用[家庭生命周期决议](01-family-membership.md#answer)保持只读，不能通过载入、复制或重新选用模板恢复协作。

### 同源去重与移除后重新选用

- 家务沿用已决同源去重：存在同源家庭家务时跳过，包括暂停中的家务，不覆盖家庭修改；确需多份时主动复制并分别命名。
- 特权在同一家庭内按同源模板与同一兑现人去重：未移除的心愿都参与判断，包括待确认、已下架条目。再次选用进入已有条目，不覆盖修改、不自动重新开放。
- 双方分别提供同一种服务时可各有一项。例如甲、乙都愿意提供按摩，可以分别确认各自提供的按摩心愿。
- 尚未确定兑现人的同源意向只保留一项。确定兑现人时若发现已有对应条目，提示使用已有条目或先移除重复意向；不自动合并内容，也不代替兑现人确认。
- 家庭家务已删除或心愿已移除后，公共模板仍已发布的，可以按当前发布内容重新选用，创建新的家庭条目。这不恢复旧条目，也不重开、覆盖旧待办、打卡或兑换记录。
- 旧心愿还有待兑现时，移除后重选不取消原承诺。旧兑换继续可查、可盖章或主动取消，新心愿仍需兑现人确认；新旧条目独立处理。原有同一心愿最多一笔未关闭兑换的规则仍按[心愿履约决议](07-wish-fulfillment.md#answer)执行。
- 暂停家务、下架心愿没有被删除或移除，不能通过重新选用绕过去重。平台修改或误下架恢复后仍是同一模板来源，也不会被当作新的模板重复添加。

### 发布、下架与误操作恢复

平台模板采用草稿、已发布、已下架三种状态。已发布模板的未发布编辑不改变当前供家庭选用的内容；保存编辑与发布是不同操作。

| 操作 | 平台维护结果 | 家庭侧结果 |
| --- | --- | --- |
| 新建或保存草稿 | 可暂存未填完整的内容 | 草稿不可供家庭选用 |
| 编辑已发布模板并保存 | 保存尚未发布的修改 | 继续提供原发布内容 |
| 明确发布修改 | 校验后更新供选用的内容 | 后续选用使用新内容；已有家庭内容不变 |
| 下架 | 停止新选用 | 选用中的旧页面需重新核对；已有家庭内容不变 |
| 重新发布 | 明确重新发布最后发布内容，或修订后再发布 | 恢复新选用，保持原模板来源及去重关系 |
| 删除从未发布的草稿 | 删除草稿 | 不影响家庭内容 |
| 放弃已发布模板的编辑稿 | 放弃未发布修改，保留原发布内容 | 家庭继续看到原发布内容 |

- 发布、下架、重新发布前说明影响范围并确认，操作后显示结果；不顺带发布尚未确认的编辑稿。
- 首版不提供已发布模板的永久删除或完整版本回滚。已经误发布的内容通过修正后重新发布处理；误下架可恢复最后发布内容。
- 管理员角色、模板操作权限与操作记录权限由[平台家庭管理、运营指标与客服权限如何划界](09-admin-permissions.md)承接，不在本工单默认增加审核角色或客服权限。

### 发布校验、排序与内容库验收

- 草稿可不完整；发布前，家务必须有名称、完成范围说明、六区归属、完整建议周期及合法分值，特权必须有名称、明确服务内容和正整数价格。发布前可预览家庭看到的内容，排序可采用默认值。
- 家务按六区分组，组内按平台顺序展示；特权按平台顺序展示。两类模板支持名称与说明搜索，家务另支持区域和周期筛选。
- 首批家务预设至少 24 项，六区每区至少 3 项，整体覆盖每日日常、每周重点和定期深度清洁，不强迫每区具备全部频率。
- 家务名称具体到可以独立完成和打卡的一项事务，说明明确完成范围，避免重复拆分计分；养宠等适用条件明确标注。建议周期和分值可以由家庭调整。
- 数量与覆盖是首批内容库的整体验收标准，不要求每次发布单条时重新凑齐数量。本轮确认标准，不以批量制作完整内容库替代决策，也未认定内容库已经制作完成。

### 选用中变更、批量结果与重试

- 提交前列明将新增、因同源跳过、需要修正或已下架的项目。同源跳过可正常继续，其他问题先处理再提交。
- 家庭预览后，选中的模板内容被重新发布或下架，提交时须提示哪些内容变化，保留勾选及家庭已填内容，重新核对后继续；不静默替换模板内容或漏载项目。下架项需从本次选择移除后才能继续载入。
- 仅排序变化不打断选用。已经成功载入的家庭内容不因随后平台修改或下架而改变。
- 一次确认中实际应新增的条目全部成功或全部不新增；同源跳过属于已说明的正常结果，不算部分失败。
- 双方同时载入同源家务时，先成功的家庭内容保留，后完成的一方显示已存在并跳过；其余实际应新增条目仍遵守本次全部成功或全部不新增的规则。
- 重复点击、网络重试或双方同时选用不能绕过去重、重复添加或覆盖先成功的家庭内容。网络返回不明时先查询该次处理结果，再继续或重试，不能把返回不明当作失败重新创建。

### 场景核对

| 场景 | 预期结果 |
| --- | --- |
| 家庭调整了换床品的周期和分值，平台后来修改同源预设 | 家庭修改保留；再次选用默认跳过，需要第二份时主动复制 |
| 家庭暂停了家务，再次全选预设 | 暂停的同源家务跳过，不自动恢复或重复添加 |
| 家庭选用按摩模板，希望伴侣提供 | 保存为不可兑换心愿，伴侣确认内容与价格后才开放 |
| 双方都愿意提供同一种按摩 | 可分别保留由甲、乙兑现的两项心愿，各自本人确认 |
| 同一兑现人的同源心愿待确认或已下架，再次选用 | 定位已有条目，不覆盖家庭改动、不自动开放 |
| 未确定兑现人的意向后来指定给已有同源心愿的兑现人 | 提示使用已有条目或先移除重复意向，不自动合并或代确认 |
| 已移除旧按摩心愿仍有待兑现，又选用当前模板 | 创建新心愿并重新确认；旧待兑现按原价格、内容、兑现人继续处理 |
| 家务已删除，模板仍已发布，再次载入 | 创建新家庭家务，旧打卡与历史安排不恢复、不覆盖 |
| 运营者保存了未发布的价格修改 | 家庭仍看到旧发布价格；原家庭心愿和兑换约定均不变 |
| 模板误下架后重新发布，家庭以前已经选过 | 恢复新选用入口，仍按原来源去重，不给家庭再添一份 |
| 家庭预览多项家务后，其中一项被下架 | 保留已填内容，提示移除下架项并重新核对后再提交，不静默少载一项 |
| 选了多项，其中部分在本家庭已有 | 已有项明确跳过，其余应新增项全部成功或全部不新增 |
| 网络结果不明后重试，或双方同时载入同源家务 | 查询并显示已处理结果，不重复添加、不覆盖先成功的家庭内容 |
| 家庭归档后尝试重新选用预设 | 保持归档只读，不能继续新增家庭内容 |

核对结果：以上场景均可按三轮已确认决定及引用的既有决议得到明确结果。此处为文档规则推演，不代表运行中的功能、页面或并发测试已通过。
