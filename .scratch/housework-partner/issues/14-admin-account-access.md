## Question

在已确认的两类管理员、独立账号与权限边界下，首版管理员从获得账号到首次进入后台、退出和恢复访问，应具备哪些用户可见路径，才能交给详细需求阶段设计？

- 第一名超级管理员如何取得可用账号；后续管理员由谁开通、通过什么用户可见方式获得登录所需信息。明确账号交付完成的判断，不在规划中创建真实账号或凭证。
- 登录使用什么账号标识与验证方式；首次使用需要完成哪些步骤；不默认存在自助注册。
- 登录失败、会话失效与主动退出后，页面如何提示及返回；已停用或降权账号的旧会话沿用既定权限限制。
- 忘记或遗失凭证时，谁能发起和完成恢复、如何确认恢复对象；唯一有效超级管理员无法登录时如何恢复访问，不借恢复入口绕过角色边界。
- 账号恢复和凭证交付需要展示哪些信息、对谁可见、有哪些必要留痕；不得引入家庭私有内容查看或家庭成员客服流程。
- 写清成功、失败、重复操作及账号状态变化下的预期结果，补入后续验收场景；只有需要提高讨论清晰度时再提出局部路径原型。

已有权限规则以[平台家庭管理、运营指标与客服权限如何划界](09-admin-permissions.md#answer)为准；已有页面组织以[平台后台如何呈现安全且够用的运营路径](11-admin-prototype.md#answer)为准。认证组件、协议、供应商、部署和凭证存储等技术方案留到后续，不因本票选择而扩大地图到技术实施。

## Answer

本决议经用户逐轮确认，仅确定首版管理员账号使用路径。固定角色、最后有效超级管理员保护及家庭隐私边界沿用[平台权限决议](09-admin-permissions.md#answer)；后台页面组织沿用[后台路径决议](11-admin-prototype.md#answer)。

### 初始超级管理员账号

- 超级管理员账号在系统初始化时，作为基础数据一并初始化。
- 初始密码默认为 `123456`；初始化账号由维护人员向本人交付账号及首次登录信息。本次规划不创建真实账号或凭据。

### 登录与后续账号开通

- 使用独立用户名与密码登录平台后台，不开放自助注册。
- 用户名唯一，创建后不可修改；停用后也不能分配给另一个人。姓名或显示名称可以修改，历史操作仍对应原账号。
- 后续管理员账号由超级管理员开通，沿用既定固定角色与管理权限。
- 后续账号初始密码同样默认为 `123456`，由开通者向本人交付账号及首次登录信息。
- 首次登录必须设置本人密码，成功进入后台后视为交付完成；初始密码不采用随机临时密码仅当次展示的方案。
- 使用默认密码登录后只能先设置本人新密码，不能进入业务页面；新密码须为 8～64 位，不能为默认密码或与当前密码相同。

### 遗失凭证的恢复责任

- 普通管理员忘记密码，由超级管理员重置。
- 所有有效超级管理员均无法登录时，通过维护渠道恢复既有账号。
- 重置前在线下确认申请人身份，不增加线上身份确认或审批流程；日常由超级管理员核实，维护恢复由维护渠道核实项目负责人。
- 重置成功后密码恢复为 `123456`，此前使用的凭据及全部旧登录会话失效；本人使用默认密码登录后必须重新设置符合上述要求的新密码，才能进入业务页面。若重置前已处于默认密码阶段，新旧默认密码文字相同，但此前会话不因此保留。
- 恢复不改变账号角色或停用状态，停用账号仍保持停用。

### 本人修改密码

- 已登录管理员可通过“修改密码”入口输入当前密码、新密码并再次确认新密码。
- 修改成功后退出全部登录会话，使用新密码重新登录。

### 登录异常、退出及权限变化

- 密码错误留在登录页提示；连续错误 5 次，暂停尝试 15 分钟。
- 30 分钟无操作，或登录满 12 小时，需重新登录。
- 主动退出或登录失效后回到登录页，未提交操作不自动补交。
- 账号停用后退出；角色变化后重新登录，按最新权限进入。旧会话不能继续执行原权限操作，沿用既定执行时核验权限的规则。

### 操作留痕与信息可见范围

- 创建账号、首次改密、本人改密、重置及维护恢复，记录操作者、时间、目标账号、动作和结果；重置及维护恢复另记录原因。
- 不记录密码或线下身份材料，不增加线上身份核验或审批流程。账号和首次登录信息按上述责任向本人交付，不以日志交付凭据。
- 超级管理员查看全部操作记录，运营管理员只看本人记录；沿用后台日志不可修改或删除的既定规则。维护恢复亦须留下可追溯记录，不借维护渠道新增后台角色、提升权限或访问家庭私有内容。

### 重复操作与失败恢复

- 重复初始化不覆盖已有账号、密码或角色。
- 同一次创建、改密或重置重复提交，只生效一次；用户名冲突不能覆盖或另建同名账号。
- 失败或结果不明时不提示成功；先核对结果，再决定是否重新操作。旧请求的重复提交不构成一次新的重置，不得覆盖其后本人已修改的密码。

### 用户路径与后续验收场景

以下为正式实现必须验证的产品预期，本次只完成规则确认与文档核对，未运行真实认证测试。

| 场景 | 预期结果 |
| --- | --- |
| 首次初始化与账号交付 | 基础数据包含初始超级管理员账号；维护人员向本人交付登录信息；默认密码为 `123456` |
| 后续管理员开通 | 仅超级管理员按既定角色权限开通独立账号，由开通者向本人交付；无自助注册路径 |
| 默认密码首次登录 | 先进入强制改密路径，改密前不能访问业务页面；本人完成设密并成功进入后台才视为交付完成 |
| 新密码边界 | 8 位与 64 位且不同于默认/当前密码的输入符合长度要求；7 位、65 位、默认密码、当前密码及两次输入不一致不能完成改密 |
| 用户名冲突与人员资料修改 | 已有或已停用账号的用户名不能重用，用户名不可修改；修改姓名/显示名称不改变历史操作归属 |
| 普通管理员遗失密码 | 超级管理员线下确认本人后重置为 `123456`，记录原因；无线上身份确认或审批步骤 |
| 唯一或全部有效超级管理员无法登录 | 通过事先约定的维护渠道线下核实项目负责人后恢复既有账号，留下操作者、目标、原因和结果，不改变角色或停用状态 |
| 重置后的密码与会话 | 旧自设密码不再可用，全部旧会话失效；用 `123456` 登录后必须先改密，不能直接进入业务页面 |
| 本人主动改密 | 输入当前密码、新密码并再次确认；成功后全部会话退出，使用新密码重新登录 |
| 连续密码错误 | 留在登录页提示，第 5 次连续错误触发暂停尝试 15 分钟；暂时限制不等于管理员被停用 |
| 无操作及登录时长边界 | 无操作满 30 分钟或登录满 12 小时需重新登录，失效会话不能继续执行业务操作 |
| 主动退出与失效返回 | 回到登录页，退出或失效的会话不可继续使用；此前未提交的业务操作不自动补交 |
| 停用或角色变化 | 停用后退出且重置不解除停用；角色变化后重新登录，直接访问及旧会话按最新权限限制执行 |
| 操作记录 | 所列账号操作留痕，重置与维护恢复含原因；超管可看全部、运营仅看本人，不含密码或线下身份材料，不能改删 |
| 重复初始化及重复提交 | 重复初始化保留已有账号、密码与角色；同次开通、改密或重置只生效一次，重复旧请求不覆盖后续改密结果 |
| 操作失败或结果未知 | 不误报成功，先核对实际结果再重试，不因此重复建号、改密或重置；重试仍按最新账号状态和角色权限处理 |
