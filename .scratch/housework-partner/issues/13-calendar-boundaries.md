## Question

在[家务周期基本规则](02-task-calendar.md#answer)已经确认的前提下，首次安排、提前完成、仅修改本次、修改长期周期和暂停恢复相互叠加时，如何确定当前与下一次待办，避免重复出现、悄然消失或改变已确认记录？

- 首次载入或新建家务从哪一天开始，是否允许过去的起点，是否补造创建前任务；每隔 N 天或 N 个月如何选择首次日期与日历起点。
- 未来预览显示的计划与已经出现的当前待办如何区分；尚未到日但可提前完成的最近一期，是否会被长期安排的修改影响。
- “仅修改本次”允许修改哪些字段，是否包括执行日期；若改日期，可否提前到过去、推迟至下一期或与下一期同日，提前完成的限制按哪个日期判断。
- 修改长期周期后已有当前待办不变，新计划的第一次执行如何确定，如何避免与当前待办日期重叠或漏掉一次。
- 当天暂停又恢复、原计划日当天恢复，以及提前完成后再暂停恢复，怎样继续原日历而不重复生成、不补发暂停任务。
- 在[平台停用恢复决议](09-admin-permissions.md#answer)基础上，家庭当天停用恢复、计划日恢复、跨期恢复与提前完成、单次改期、轮流叠加时，怎样衔接原待办和恢复后的计划；区分家庭停用与单项暂停，不重开已决的原待办保留、跨期关闭、不补发、已完成不重复及原单项暂停不解除原则。
- 依据[打卡与反馈决议](04-checkin-and-feedback.md#answer)，改期或调整周期后再撤销完成时，怎样判断该次仍可处理还是已经成为历史；保留已决的恢复归属、暂停删除不重开及后续轮次不重排，不把更正实际完成日期当作修改计划日期。
- 在[分配与轮流决议](03-assignment-rotation.md#answer)基础上，本次改期、长期周期修改、未来预览与当天暂停恢复如何确定对应的计划次序和负责人；保留当前待办时如何衔接后续轮流，避免同一次因改期重复占轮次。此处明确日期组合边界，不重开按计划轮流、暂停期间沿原日历推算、单次接手不改后续轮次等已决原则。
- 用每天洗碗、每周换床品、每隔数月深度清洁和一次性家务走通以上边界；本工单不重开固定日历、历史保留和家庭归档的已决选择。

## Answer

三轮用户确认形成以下规则，作为日期组合边界的唯一决议入口。既有本人打卡、分值、权限、暂停、历史保留及家庭归档规则继续适用；本工单补全日期衔接，不改变这些前提。

### 首次安排

- 新建或从预设载入家庭家务，只从今天或未来开始，不补造创建前的待办。
- 每天默认今天，也可选择未来开始日；每周取不早于所选开始日的首个指定星期。
- 每隔 N 天以所选首次日期为日历起点；每隔 N 个月以所选首次月份和指定日为起点。首次实际执行日不得早于今天，月末缺日按已决规则落在当月最后一天，不改变长期指定日。
- 一次性家务选择今天或未来的执行日期。

### 未来预览与已固定的本次

- 单纯浏览未来预览不固定那次安排；长期计划修改后，尚未固定的预览随之更新。
- 到计划日，或用户对可操作的最近一期成功认领、接手、单次修改、跳过或提前完成后，形成需要保留的那一次执行，后续长期修改不能覆盖它。
- 上述边界不放宽既有提前完成限制，也不允许通过预览操作更后一期。

### 单次改期的基本范围

- 未完成本次允许调整执行日期，只能改到今天或未来。保留原计划日期供追溯；改期仍是同一次执行，不额外占轮次。
- 周期家务的单次执行日期须早于当前有效计划的下一期，不允许与下一期同日或跨过下一期；未修改长期周期时使用原日历下一期，修改长期周期后使用最后确认的新计划第一次。一次性家务没有下一期限制。

### 单次可改字段

- 未完成本次可以修改名称、说明、区域、分值、本次负责人和本次执行日期，不修改重复方式、长期分工或以后各次。
- 分值、负责人继续遵循既有权限、取值和同时操作规则。已完成记录沿用既有更正或撤销流程，不由仅修改本次改写。

### 改期后的到期与提前开放

- 是否到期、是否逾期按本次执行日期判断，当天结束后仍未完成才算逾期。
- 后一期的提前操作至少等到原计划日期和本次执行日期中较晚的那一天结束，且当前这次仍未完成时，继续优先处理当前这次；到下一期计划日再按不积压规则收尾。
- 周日换床品提前到周五并完成，仍须等周日结束才允许提前操作后一期；推迟到下周三，则按周三判断到期和提前开放下限，后续周日仍按原日历执行。

### 修改长期周期后的接续

- 保留已经固定本次的内容、原计划日期、本次执行日期和负责人。尚在提前开放限制内的已完成或已跳过本次，也需要保留。
- 设置新周期时明确确认新计划第一次；该日期不能早于今天，并须晚于保留本次的原计划日期和本次执行日期。没有需要保留的本次时，新计划可从今天或未来开始。
- 旧次未完成时保留到新第一次到来，再转为未完成历史。这会调整旧次的收尾日期，保存前必须明确展示，不改写已有打卡。
- 示例：周日换床品已推迟到周三，随后改成每周五，保留周三这次，新计划从之后的周五开始；到周五仍未完成，周三这次转为历史。
- 新第一次须符合所选重复规则。每隔 N 天以新第一次为日历起点；每隔 N 个月以新首次月份和指定日为起点，缺日取当月末日，不改变以后月份的长期指定日。
- 长期新计划确认后，其第一次日期取代旧下一期，成为当前一次的接续日期；此后单次改期必须早于它，不能通过仅修改本次自动推迟新第一次。
- 反复修改长期计划只替换尚未固定的未来安排，已固定的最近一期继续保留；已经成为历史的旧次不因把未来日期推远而重开。已有打卡不改写。
- 保存前明确展示保留哪一次、旧次何时收尾、新第一次日期与负责人。

### 单项暂停恢复

- 已经因暂停关闭的那一次，当天恢复或反复暂停恢复均不重开；已完成、已跳过同样不重复生成。
- 恢复当天是原计划日，且该次从未生成，则允许当天生成一次。非计划日恢复不补发过去任务，继续未来最近一期。
- 提前完成后暂停恢复，保留该完成记录与后一期提前开放限制。
- 一次性家务已因暂停关闭时，恢复不重开同一次，需要时另建；首次日期尚未来临且未形成具体待办时，恢复后仍按原日期执行。

### 周期变化与轮流衔接

- 保持轮流分配且有需保留本次时，新计划第一次接续该次的计划轮次，不按实际完成人重新排。若本次原计划轮到 A，即使 B 接手完成，新第一次仍轮到 B；本次改期仍只占原来一个轮次。
- 未固定且因长期修改被替换的未来预览不占轮次。预览展示预期负责人，固定后按当前一次保护，不因后续长期修改换人。
- 暂停、平台停用期间继续沿当时有效日历推算轮次，不生成待办、不记漏做、不补发。恢复操作本身不多占轮次，也不能以暂停前最后一个实际完成人或固定旧次重启轮流。
- 没有需保留本次时，接续当时有效日历中下一轮的应负责人；若首次轮流尚未开始，保留已选首位。重新启用轮流仍按既定规则重新选择首位，从首个新待办生效。

### 平台停用恢复

- 平台停用前未完成待办保留只读；停用期间不能修改安排、认领、打卡、补记、更正或撤销。家庭归档不可恢复，单项暂停不因平台恢复而解除。
- 以停用前最后确认的接续日期判断周期旧待办是否跨期。未跨期则恢复原待办，保留已改期、认领、分工等结果，包括已提前固定的未来一期；跨期则注明“平台停用”并关闭，不计漏做。
- 恢复当天恰为有效计划日，且该次不存在时，生成一次；否则不补发停用期间各次，继续未来安排。恢复日和接续日相同即已到下一期，不能同时把旧次恢复为当前待办。
- 已完成、跳过或因单项暂停关闭的那一次不重建；原单项暂停不解除。提前完成的原记录与提前开放限制保留，停用恢复本身不额外推进轮流。
- 一次性家务无下一期，停用前已存在的未完成待办恢复后继续保留，与单项暂停关闭当前一次的规则不同。

### 撤销完成、更正日期与历史边界

- 接续日期已经到来，或下一期已因提前认领、接手、单次修改、跳过或完成而固定，均视为已进入后续一次。此时撤销旧完成只恢复未完成历史，不把旧次重新开放为当前待办，不影响已固定的后一期。
- 单纯浏览后一期不构成进入后续一次。后一期尚未固定、接续日期尚未到，且没有暂停、删除等关闭限制时，撤销恢复原来那一次，保留其单次修改，负责人保留为撤销前完成人；是否逾期按该次执行日期判断。
- 已转历史或曾因暂停关闭的记录不因后来恢复、改周期或撤销而重开。原为历史补记的完成撤销后仍是历史，不反向恢复待办。
- 平台停用期间不能撤销；平台恢复后，再按该次是否跨期、是否已进入后续一次及既有关闭状态判断。家庭归档后继续只读，不允许撤销。
- 更正实际完成日期不改变计划日期、本次执行日期、接续日期或后续轮次。撤销资格、本人身份、原因留痕、积分扣回及重新打卡继续遵循[打卡与反馈决议](04-checkin-and-feedback.md#answer)和[积分决议](05-points-ledger.md#answer)。

### 一次性家务与重复方式切换

- 首次执行尚未形成具体待办，但日期已在单项暂停或平台停用期间过去，恢复后不补造，明确展示“日期已过，未生成待办”，需要时另建一次性家务；不把未生成的待办记为漏做或可补记历史。
- 恢复恰在首次日期当天，且该次从未生成时，可按恢复日规则生成一次。已有的一次性待办继续区分平台停用保留与单项暂停关闭，不能以“日期已过未生成”替代已有记录。
- 首版允许周期家务内部修改重复方式，不在原家庭家务内直接互转一次性与周期；需要互转时结束旧安排并另建，保留旧历史。一次性家务仍不采用轮流分配。
