# 小程序完整路径粗原型

用于审阅[小程序四个模块与家庭设置如何组成清晰路径](../../issues/10-app-journey-prototype.md)。**导航与关键路径决策已于 2026 年 9 月 9 日结案（resolved），采用 B「家庭首页」。最终选择、用户确认与验收边界见工单 Answer；这是粗原型，不代表正式产品验收通过。**

沿用已确认业务规则及协作天平 B「双方对照」。本轮 A/B/C 比较的是全局导航，不重开天平布局。

后续审阅已确认：任务大厅保留当前待办、未来预览、全部家务三个入口。普通及提前打卡成功后留在原任务视图，保留筛选，显示完成/积分提示与一次撒花；主动点击“查看记录”后才进入对应动态。历史补记仍沿用独立流程，本次确认不扩展其页面去向。

用户另已确认：心愿兑换成功后直接进入待兑现列表，方便找到该笔约定并进行后续盖章或取消；沿用原型既有实现。

入口布局后续调整：B 任务大厅右上角固定“＋ 添加家务”，点开直接进入预设清单，同页切换到自行创建，切换保留当前输入和预设勾选。底部原三入口已移除，家庭设置继续从底栏进入；未完成历史与补记从动态打卡簿顶部的“以前做过，忘记打卡了？／补上打卡”入口进入。自建家务预览后返回修改，会回到原页并保留表单。

记录页改版已保留：用户反馈需要听解释才能分清操作，因此去掉“历史补记”筛选标签，已有本人记录只留“修改记录”。点击后按“日期或文字写错了／这次打卡记错了”选择，各选项直接显示积分不变或扣回分值；最终撤销确认展示余额前后值、留痕及家务去向。用户对改版回复“好的，继续”，据此保留该层级；后续审阅现已记录在工单 Answer，不扩大为正式产品验收通过。

根据用户指出详情操作过多的反馈，已改为分层版：任务详情展示本次日期、负责人和分值，只突出当前主操作与“调整这一次”。本次修改、跳过和放回待认领在调整页解释何时使用；长期周期、暂停／恢复改从“全部家务 → 管理这项家务”进入，复制和删除收在更多管理操作。用户随后回复“好的，还不错。继续”，据此保留该层级；后续路径确认与结案见工单 Answer。

## 启动

从项目根目录运行：

```sh
python3 -m http.server 8768 --bind 127.0.0.1 --directory .scratch/housework-partner/prototypes/app-journey-prototype
```

打开 [原型 A](http://127.0.0.1:8768/?variant=A)、[原型 B](http://127.0.0.1:8768/?variant=B) 或 [原型 C](http://127.0.0.1:8768/?variant=C)。也可直接打开 `index.html`，无需安装依赖。静态 HTML/CSS/JavaScript，状态仅在内存，刷新重置；固定演示日为北京时间 2026 年 9 月 8 日。

## 建议试走

普通首次进入只显示“创建我的家庭”；受邀人从微信分享邀请卡片进入邀请详情，查看家庭与邀请人后确认加入。此原型未接入真实微信分享，使用演示台“受邀加入 · 有效邀请／邀请已过期”体验对应页面。欢迎页不再提供直接模拟有效邀请的按钮。

1. **首次起步**：演示台选“首次进入” → 创建家庭 → 选家务并预览，或暂时跳过 → 单人任务大厅 → 家庭设置 → 邀请卡片预览。微信分享不真实发送，可用演示台模拟伴侣加入；受邀及过期邀请有独立场景。
2. **完整协作**：双人场景 → 照料阳台植物 → 认领本次 → 本人打卡（可清空全部日期与文字）→ 动态 → 天平 → 积分流水 → 心愿集市 → 兑换肩颈按摩 → 待兑现 → 盖章或取消。种子数据另保留原心愿已移除的待兑现约定。
3. **记录与账目**：未完成历史 → 本人确认后补记 → 日期留空或填写上月 → 更正日期 → 查看天平月份 → 填原因撤销 → 查看原流水及关联扣回。比心仅出现在伴侣有效记录上。
4. **本次与长期**：换洗床品 → 仅修改本次的日期或分值 → 全部家务查看长期值和本次值 → 修改后续安排 → 保存前核对保留本次、接续日期、首两次负责人。未来预览包含最近一期及不能提前操作的后续说明。
5. **异常与恢复**：演示台选择下一次提交明确失败或返回不明 → 提交 → 保留表单重试或查询本次结果。查询后只显示原结果，不再次变更积分或撒花。
6. **家庭边界**：演示台选家庭停用 → 查看原因、历史、被收起的写入口 → 模拟平台恢复，或本人退出 → 两次确认 → 全家归档、待兑现退分 → 新建家庭与旧家庭只读历史来回查看。

## 实现与验证边界

- 这是导航及交互讨论用的可丢弃代码，不是正式小程序，不连接微信登录、分享、头像上传、服务器或真实家庭数据。
- 交互覆盖上述主要路径；日历固定在演示日，未实现时间推进、任意历史轮转及完整跨期调度。`日期与恢复说明`呈现前序决议的固定场景结果，不能作为日期算法已实现的证据。平台恢复按钮只演示未跨接续日的恢复。
- 本次值与长期值分别保存；周期首次日、单次改期上限、一次性不能直接转周期等有本地输入约束。后续日期预览为审阅用，不是完整调度引擎。
- 结果不明模拟“操作成功、响应丢失、查询返回原结果”；明确失败保留输入。未连接真实幂等键、服务端事务、同时认领或兑换竞争，也未模拟模板重新发布/下架竞态。
- 六个家务预设仅是试走样本，**不代表首批至少 24 项的内容库已完成**。特权价格为示例，不是产品定价决议。
- 只有本人账号可打卡。演示台“伴侣加入”和“平台恢复”只改变模拟场景，没有代伴侣确认、代打卡或切换身份入口。
- 用户已确认导航 B 和工单 Answer 中的关键路径；尚无真实双人试用，不宣称所有交互与组合逐项通过。业务规则仍以关联工单 Answer 为准，遇到规则缺口需提出问题并经用户讨论，不在原型中默认确认。

## 留档与后续

添加家务页的“全选／取消全选”按用户反馈移至预设清单顶部，位于说明下、第一项预设前；底部保留预览载入和暂时跳过。

家庭设置按用户要求精简：“这个家的安排”只展示全部家务、家庭心愿、积分与流水、家庭与本人资料，移除其中的“已归档家庭”和“日期与恢复说明”入口。

待兑现卡片按用户要求移除“修改备注”入口，“取消并退分”改为整行按钮；兑换人看到两个上下排列的整行操作。已有约定备注继续展示。用户试用后回复“我觉得可以了”，保留本轮布局、取消确认与退分反馈；家庭设置等后续确认见工单 Answer。

心愿完成操作已按用户确认改为“我已收到，确认完成”，卡片与二次确认使用相同文案。确认成功后在手机预览内显示短暂盖章反馈；明确失败不盖章，返回不明则查询到结果后才盖章。积分及已决完成权限、不可撤销规则不变。
