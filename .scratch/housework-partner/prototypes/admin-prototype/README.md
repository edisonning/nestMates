# 平台后台交互粗原型

用于审阅[平台后台如何呈现安全且够用的运营路径](../../issues/11-admin-prototype.md)。用户已确认 Q1～Q6：固定左侧导航、独立家庭详情、编辑并排对照，以及家庭、模板、概况、管理员、日志和异常提示的当前呈现。最终决议以所属工单 Answer 为准。

静态 HTML/CSS/JavaScript，模拟数据、内存状态，无真实接口和持久化。可以直接打开 `index.html`，或从项目根目录运行：

```sh
python3 -m http.server 8767 --bind 127.0.0.1 --directory .scratch/housework-partner/prototypes/admin-prototype
```

浏览器访问 `http://127.0.0.1:8767/`。右上方显示当前管理员；顶部紫色折叠区属于原型演示台，可切换身份、页面状态及下一次提交的异常，刷新重置数据。

## 建议按这四条路径试走

1. **家庭停用与恢复**：家庭管理 → 梧桐小家 → 填原因 → 查看影响并停用 → 确认 → 填恢复原因 → 查看影响并恢复。检查双方可见原因、状态和恢复路径是否清楚。
2. **保存与发布**：公共家务预设 → 更换床品。左侧 40 分为当前发布内容，右侧 50 分是编辑稿；保存后左侧不变，预览并确认发布后才更新。下架后可重新发布最后发布内容。
3. **有编辑稿时恢复下架模板**：默认特权模板 → 周末早餐。最后发布价格 80 分、编辑稿 120 分；重新发布最后发布内容只恢复 80 分，编辑稿仍保留。
4. **权限和失败**：展开原型演示台，切换运营管理员，尝试直接访问家庭详情和查看本人操作记录。再重置，模拟恢复前家庭已归档、当前账号已停用、明确失败等状态。

补充检查：管理员管理尝试降级最后一名超级管理员；保存不完整草稿后尝试发布；检索不存在的家庭；模拟无数据与读取失败。

## 演示边界

- 少量模板仅为试走数据，未制作完整首批内容库。全平台指标为独立的模拟汇总，不由四户样本反推。
- 家庭成员页、日历恢复算法、真实角色鉴权、并发请求、登录及凭证交付不在本原型实现中；此处显示它们对后台操作者有用的结果说明。
- 管理员新增只模拟独立账号、固定角色与原因，不生成或发送真实凭证。真实账号开通及登录流程需在详细需求中补齐。
- 目前展示“明确失败”的重试；没有把网络结果未知冒充明确失败。
- 模板排序使用数值越小越靠前，作为本轮确认的界面约定。
- 不含客服、反馈、账号注销、私有家庭记录查看、改分或代操作入口。
- 无正式产品开发、技术选型或生产验收。本工单已 resolved；用户确认限于粗原型页面与运营路径，最终 Answer 已记录。

路径选择与初始草图见 [path-proposal.md](path-proposal.md)，浏览器检查见 [verification.md](verification.md)。
