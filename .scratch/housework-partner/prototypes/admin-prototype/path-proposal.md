## 本轮要回答的问题

运营者能否找到有权执行的动作，并在提交前理解影响、提交后识别结果和恢复办法？先确认下面三个布局选择，再用模拟数据制作可点击页面，验证正常与异常路径。

| 待确认选择 | 推荐方案 | 其他候选及取舍 |
| --- | --- | --- |
| 主导航 | A：固定左侧导航，持续显示所在模块，按角色隐藏无权入口 | B：任务首页先选“看概况／维护模板／处理家庭”，少展示常驻导航但多一步；C：顶部模块导航，适合模块少的宽屏，长名称占横向空间 |
| 家庭详情 | 独立详情页，状态、成员、操作记录与处理区放在同一页 | 右侧抽屉便于连续查看，但影响说明及历史记录空间较窄 |
| 模板编辑 | 当前发布内容与本次编辑并排，保存与发布分开 | 平时单栏编辑，仅在发布确认时对照，编辑更集中但较晚发现生效内容的差异 |

用户本轮已逐项选择三个推荐方案。以下据此推进模拟页面，后续体验问题 Q4～Q6 也已确认，最终 Answer 已记录。

## 页面入口草图

```text
家务搭档 · 平台后台                         当前管理员与角色
│
├─ 运行概况          今日 / 近 7 日 / 近 30 日 · 北京时间
│                    家庭组建 → 家务协作 → 兑换与兑现
│                    全平台指标及口径说明
│                    独立快捷入口：维护公共模板 / 家庭管理（有权时）
├─ 家庭管理          名称或编号检索、状态筛选 → 家庭详情
├─ 公共家务预设      搜索、状态、区域、周期筛选 → 编辑 / 新建
├─ 默认特权模板      搜索、状态筛选 → 编辑 / 新建
├─ 管理员管理        账号列表 → 角色和启停操作
└─ 操作记录          全部记录 / 本人记录（按角色决定）
```

家庭管理、管理员管理仅超级管理员可见。概况数字不下钻家庭私有记录；进入家庭管理使用独立模块入口，不把“协作活跃家庭数”变成家庭贡献榜单。

## 家庭处理路径草图

```text
家庭列表
  家庭编号｜名称｜成员数｜状态｜创建日期｜最近协作日期｜查看
      ↓
家庭详情
  名称与编号、当前状态、创建日期、最近协作日期
  成员编号｜昵称｜加入日期
  家庭状态操作记录：操作者、时间、动作、结果、原因
      ↓
使用中：停用家庭       停用：恢复家庭       归档：只读，不可恢复
      ↓
填写双方可见原因 → 查看影响并再次确认 → 执行结果
```

停用确认建议文案：“该家庭将暂停协作操作，成员关系、历史、积分与待兑现保留。双方仍可查看有权访问的历史或本人退出。原因会向双方展示。”

恢复确认建议文案：“该家庭将恢复使用，沿原日历继续，不补发停用期间待办；原先单独暂停的家务仍暂停。成员、积分和待兑现保留。原因会向双方展示。”

结果建议留在当前详情页：成功后显示最新状态、执行时间和双方可见原因；停用成功后提供恢复入口。恢复仍需重新填写原因和确认，不做一键撤销。执行失败明确显示“本次操作未生效”，保留输入并允许按最新状态继续处理。若家庭已归档，则说明已归档、不可恢复。

## 模板维护路径草图

```text
模板列表 → 新建草稿 / 编辑已有模板
                ↓
      当前发布内容       本次编辑内容
      家庭现在可选内容   尚未发布的修改
                ↓
       保存草稿或编辑    预览并发布
                          ↓
                    校验 → 家庭视角预览
                          ↓
                  生效范围说明 → 确认 → 结果
```

- 家务编辑呈现名称、完成范围、六区归属、完整建议周期、10～100 的十档分值及排序；特权编辑呈现名称、服务内容、正整数建议价格及排序。
- 草稿允许不完整保存；校验失败定位缺少的字段，保留输入，不进入发布成功态。
- “已发布 · 有未发布修改”同时表达发布状态与编辑状态，不把“保存成功”显示成“发布成功”。
- 发布说明：“仅影响之后选用此模板的家庭；已经载入的家务、心愿及已有兑换约定不变。”特权家庭预览说明还须提示选用后仍需兑现人确认。
- 下架说明：“停止新的选用，家庭已有内容不变。”已有编辑稿不随下架被发布。
- 已下架模板分开呈现“重新发布最后发布内容”与“编辑后预览发布”；如存在编辑稿，前者明确不包含该稿。
- 放弃未发布编辑前说明保留哪份发布内容；只有从未发布的草稿提供删除。误发布通过修正后重新发布处理，不增加完整版本回滚。

## 管理员与记录路径草图

管理员列表 → 选择账号 → 调整角色或启停 → 填写原因 → 展示变化并确认 → 显示结果。

最后一名有效超级管理员的停用或降级动作不可生效，页面就地解释原因。当前角色和账号状态在执行时再次核对；旧页面不能继续行使被撤销的权限。账号开通与登录凭证的具体机制不由本布局草案假定。

操作记录按权限显示操作者、时间、对象、动作、结果和适用的原因；不添加编辑、删除入口，不在日志中附带家庭私有内容。运营管理员看到“本人操作记录”，不呈现其他人的记录。

## 可点击原型的试走清单

| 场景 | 要观察的页面结果 |
| --- | --- |
| 从概况进入模板维护 | 能找到模块入口，指标不是私有数据下钻入口 |
| 按编号找到家庭并停用、再恢复 | 最少字段、原因、影响确认、最新状态和恢复路径清楚 |
| 运营管理员直接访问家庭页 | 权限不足页，不出现家庭字段；提供可访问的返回入口 |
| 提交前管理员被降权或停用 | 拒绝原权限操作，不误报成功 |
| 停用家庭在恢复提交前因成员退出归档 | 显示已归档、未恢复，不能绕过状态限制 |
| 保存已发布模板的修改 | 家庭当前发布内容保持不变，编辑稿独立可见 |
| 发布校验未通过 | 缺项清楚，输入保留，可以修正后重新预览 |
| 下架后重新发布最后发布内容 | 恢复新选用，未发布编辑稿不被顺带发布 |
| 停用或降级最后一名有效超级管理员 | 解释不能操作的原因，账号状态不改变 |
| 没有数据或检索无结果 | 区分首次无数据与筛选无匹配，后者可清除筛选 |
| 操作明确失败 | 显示未生效及可用重试方式，不改变模拟状态 |
| 运营管理员查看日志 | 仅本人记录，不能通过对象链接绕过权限 |

浏览器验证将使用明确标注的模拟数据与内存状态。不会将前端演示权限当作真实服务端鉴权证明。日期恢复组合细节继续由[日期调整与恢复如何避免待办重复或消失](../../issues/13-calendar-boundaries.md)承接。
